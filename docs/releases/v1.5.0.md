model and analytical report, with documented measures and reconciliation
evidence.

  - Product Analysis.
  - Customer & Territory Analysis.
- Validation page retained for maintenance and hidden from normal navigation.
- Report guide, semantic model documentation and DAX catalog.
- Five screenshots covering report pages, baseline and model.

## Operational Scope and Limitations

The report uses Import mode. Warehouse ETL, Desktop refresh and Service
publication are separate operations.

Gateway installation and scheduled refresh were explicitly deferred to
a future update and are outside the agreed Module 7 closure scope.
They have not been validated.

The current manual update workflow is:
1. Execute and verify the warehouse ETL.
2. Refresh the Desktop working copy.
3. Save and republish to the same Service workspace.
4. Synchronize the repository PBIX when recording a new report version.

Publication to My workspace does not demonstrate sharing with other users.

The existing incremental ETL does not propagate physical source deletions.
The controlled test explicitly restores its source and fact data.

The insertion fixture suppresses source trigger side effects within its
controlled transactions; it is a development test, not a normal sales entry.

The repository screenshots document the final report and restored baseline.
They do not include the separate before/after screenshots reviewed during
the controlled insertion session.

## Key Learning Outcomes

- Warehouse grain and surrogate keys support consistent analytical filtering.
- Explicit measures evaluate results in the current filter context.
- Distinct order counts are not additive across overlapping product groups.
- Ratios must be recalculated from their components at each aggregation level.
- Date roles answer different business questions using the same calendar.
- Import-mode reports require refresh to observe warehouse changes.
- A published report is distinct from an automatically refreshed model.
